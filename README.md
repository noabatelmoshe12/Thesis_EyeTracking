# Thesis EyeTracking Project

This project implements a Variable Attribute Decision-Making Task using Psychtoolbox and EyeLink, followed by a comprehensive data analysis pipeline combining MATLAB and Python.

`<participant_number>` is a placeholder for the numeric participant number assigned within the study and is not part of the actual filename. Participant numbering starts at `101` for Experiment 1 and at `201` for Experiment 2.

Examples:

- `101_detailed.csv` — participant 101 from Experiment 1
- `201_detailed.csv` — participant 201 from Experiment 2

##  Installation & Setup

1. **Python Setup**: This project uses `uv` for fast and reproducible dependency management. From the project root, run:

   ```powershell
   uv sync
   ```

   This creates a `.venv` virtual environment and installs the dependencies declared in `pyproject.toml`, including `matlabengine==25.1.*`.

2. **MATLAB Installation**: MATLAB must be installed separately. This project has been tested with MATLAB R2025a and `matlabengine==25.1.*`.

3. **Experiment Dependencies**: Running `src/experiment/DM_main_noa.m` requires Psychtoolbox 3, the EyeLink Toolbox and compatible EyeLink hardware, `edfmex`, the external `Demographics` function, and the MATLAB Statistics and Machine Learning Toolbox for the post-experiment `glmfit` analysis. These experiment dependencies are not installed by `uv sync`.

##  Architecture & Data Flow (Pipeline)

The experiment and the eye-tracking analysis are separate workflows. `run_full_pipeline.py` performs the eye-tracking analysis and does not run the experiment.

### 1. Data Collection (Experiment)
* **Script**: `src/experiment/DM_main_noa.m`
* **Action**: Runs the decision-making task in Psychtoolbox, records eye position and behavioral responses, receives the EyeLink EDF file, and automatically converts it with `edfmex` into a MAT file containing `edfStruct`.
* **Outputs**: When MATLAB's working directory is `src/experiment/`, the experiment saves `Subject_<participant_number>_Demographics.mat` and `Subject_<participant_number>_Results_Decision_Strategy_Experiment.mat` there, and saves `Subject_<participant_number>_eyeData.mat` under `src/experiment/Eyedata/`.
* **Analysis preparation**: Manually place each required `Subject_<participant_number>_eyeData.mat` file in `data/raw/` before running the analysis. The active analysis pipeline reads the MAT file directly and does not use EDF files, behavioral result files, or demographic files as inputs.

### 2. Feature Extraction (MATLAB)
* **Script**: `src/analysis/matlab/Convert_eye_data.m`
* **Input**: `data/raw/Subject_<participant_number>_eyeData.mat`, containing an `edfStruct` variable.
* **Action**: Detects fixations from gaze samples, maps each fixation to predefined Areas of Interest (AOIs), and exports a detailed fixation-level CSV for downstream analysis.
* **Output**: `data/processed/fixations/<participant_number>_detailed.csv` (contains a chronological sequence of AOI labels and exact fixation timings per trial).

### 3. Transition Analysis and Scanpath Index Calculation (Python)
* **Script**: `src/analysis/python/analyze_movements.py`
* **Action**: Reads the fixation sequences and, for each trial, examines **only consecutive fixation pairs** in the original recorded order (FixationSeq i and i+1). There is **no bridging** over invalid AOIs (e.g., NaNs, blinks, or labels that do not match ATi/Ai/Bi), and invalid pairs are simply ignored and never turned into later inferred movements. A movement is recorded only when both AOIs in the consecutive pair are valid (ATi, Ai, or Bi) and their labels differ. Each valid pair is then classified as:
*  - **Horizontal**: Two **different** valid AOIs with the **same row index**, even if the kinds differ (e.g., `A1 -> B1`, `AT1 -> B1`, `A1 -> AT1`).
*  - **Vertical**: Same AOI kind **within an alternative** (only `A`→`A` or `B`→`B`) with **different row indices** (e.g., `A1 -> A3`, `B2 -> B4`).
*  - **Ignored**: Any other valid transition that is neither Horizontal nor Vertical (e.g., `A1 -> B2`).

  Examples that illustrate this logic:
  - `AT1 -> B1` is classified as **Horizontal**.
  - `A1 -> A3` is classified as **Vertical**.
  - `A1 -> B2` is classified as **Ignored**.
  - `AT1 -> AT1` produces **no movement** (identical AOIs are skipped).
  - `AT1 -> NaN -> B1` produces **0 movements**, because only the consecutive pairs `(AT1, NaN)` and `(NaN, B1)` are checked, and both involve an invalid AOI.

* **Outputs**:
  - Detailed trial transitions: `data/processed/movements/<participant_number>_movements.csv`. The file contains one row per recorded valid-AOI transition. A trial with no recorded transition is retained as a placeholder row with `Move_Index = 0` and `Classification = None`.
  - Trial summary: `data/results/trial_results_summary.csv`. The Scanpath Index is calculated for each trial as **H / (H + V)** and stored in the exact output column `ScanIndex_trial`. `Ignored` transitions are excluded, and trials with no Horizontal or Vertical movements receive `NaN`.

##  Usage Guide (How to Run)

To run the eye-tracking analysis from raw eye-data MAT files through trial-level Scanpath Index output, first place the required `Subject_<participant_number>_eyeData.mat` files in `data/raw/`. Then execute the following command from the project root:

```powershell
uv run src/analysis/python/run_full_pipeline.py
```

**What this does under the hood:**
1. Creates the required runtime data directories when they do not exist.
2. Starts the MATLAB Engine and calls `Convert_eye_data` for every matching `data/raw/Subject_*_eyeData.mat` file.
3. Calls the movement-processing functions in `analyze_movements.py` for each non-empty fixation CSV and writes `<participant_number>_movements.csv`.
4. Aggregates all movement data, calculates `ScanIndex_trial`, and writes `data/results/trial_results_summary.csv`.

##  Troubleshooting

- **Path Issues / File Not Found**: Always execute `uv run` commands from the **root** folder (`Thesis_EyeTracking`).
- **MATLAB Engine**: Processing raw eye-data MAT files requires an importable MATLAB Engine for Python. The current MATLAB command-line fallback references `run_batch_analysis.m`, which is not present in this repository and is therefore not usable.
